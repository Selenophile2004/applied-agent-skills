# Websites, interfaces and visual assets

- Inspect relevant routes/components, shared styles, package commands and existing assets before generating replacements. Preserve the current brief, approved design direction, language, accessibility and responsive behavior.
- Make focused component, style and content changes. Reuse real logos, fonts and media; inspect metadata and targeted previews instead of repeatedly loading whole asset libraries.
- Reuse build, export and packaging scripts. Persist verbose logs when useful and surface failures plus a concise result. Avoid dumping bundles, entire generated exports or base64 media into context.
- Scope browser inspection to the question and obey the chosen tool's rules. Capture fresh evidence when UI state changes; reuse unchanged evidence only while it remains valid.
- Validate affected user flows, representative screen sizes and relevant build/tests. Changes to shared layout, state or rendering may require broader checks. Preserve required visual inspection and design fidelity.
- For new builds, establish coherent reusable components and assets instead of generating each page independently. Avoid extra frameworks or dependencies that do not serve the brief.
- Deliver the requested runnable project, editable design or deployment package. Distinguish build success from real interaction and visual verification, and state remaining gaps accurately.
